What Actually Predicts Search Position — And What Doesn't

Joshua Kotze · FlyRank ML Internship Capstone · March 2026 warehouse data · Repository →

Abstract

This paper asks whether same-day behavioral signals — search impressions, engaged sessions, traffic source, AI-referral sessions, and scroll activity — can predict a content item's average Google search position for a client not seen during training. Using 9.8 million content-day rows from FlyRank's March 2026 warehouse, I built a rule-based prioritization baseline (flagging visible-but-poorly-ranked content) and a Random Forest regression model, evaluated under a client-grouped train/test split to prevent identity leakage. The rule-based baseline, grounded in a validated signal (CTR falls monotonically as position worsens), produced a defensible, honestly-scoped action queue of 6,036 content items. The regression model did not beat a naive baseline once client leakage was removed (R² = −0.0074) — a genuine, reported negative result. The paper's recommendation is therefore to ship the validated rule, not the unvalidated model, and to treat this as a template for how "the model didn't work" is still a usable finding.

Introduction

FlyRank's platform helps content teams decide where to focus limited editorial and technical effort. One recurring question from the March 2026 live session was whether a small set of easily-logged, same-day behavioral signals could reliably forecast search ranking outcomes — specifically, average Google position — well enough to prioritize a content team's week.

This paper works through that question for one lane: Ranking Signal Analysis. It follows the arc the internship itself was structured around — write a data contract, verify signals before trusting them, build a transparent baseline rule, attempt a model, validate that model honestly, and only then write recommendations. The honest result — that the model underperformed a simple baseline once evaluated correctly — is reported as a finding, not hidden as a failure.

Methodology

Label and features

Label: gsc_avg_position. Final features (5): gsc_impressions, ga4_engaged_sessions, sessions_organic, sessions_ai, scroll_events — each verified to be logged same-day and not algebraically derived from the label.

Signal verification, before building anything

Signal testResultVerdict
CTR vs. position bucket0.48% → 0.35% → 0.28% → 0.13% (positions 1–3 → 20+)CONFIRMED
Impressions vs. scroll events0.023 → 0.083 → 0.295 across volume bucketsCONFIRMED (weak effect size)

The CTR-vs-position result is what the baseline rule leans on: it is the same logic behind FlyRank's own CTR-fix flag, re-verified independently on this data slice rather than assumed.

Baseline rule

Content is flagged VISIBLE_BUT_POOR_RANK when it has real impressions (>0) but ranks worse than page one (gsc_avg_position > 10). Score = impressions × (position − 10), aggregated to one row per content item across the month, not per content-day — an aggregation fix made after an early pass showed the same page being flagged up to 10 times as if it were 10 separate opportunities.

Validation design

Split by client_hash_id using GroupShuffleSplit (80/20), with zero client overlap verified between train and test. This replaces an earlier ungrouped random split, which almost certainly let the model implicitly learn client-specific patterns rather than a generalizable signal.

Leakage audit

Deliberately re-adding gsc_sum_position to the feature set raised R² from 0.0033 to 0.0624 — roughly 19×, confirming real leakage from a label-derived field. The final 5-feature set excludes this and all other label-derived columns.

Both models score negative — neither beats simply predicting the average position for a client the model has never seen. Random Forest is marginally less bad than the linear baseline, but "less bad" is not "good." With only 5 same-day behavioral features, this data does not meaningfully predict ranking position for a new client.

Honest framing This is a real regression from an earlier, ungrouped-split result (R² = 0.0033) that looked positive. The drop reveals that the earlier number was very likely inflated by client-identity leakage between train and test — exactly the failure mode grouped validation exists to catch. The grouped number is the trustworthy one, even though it is worse.

What the model leans on

Permutation importance ranks sessions_organic highest (0.025), then gsc_impressions (0.012) — both far ahead of the remaining three features, all near zero. These values are uniformly small, consistent with the near-zero R²: the model is not leaning heavily on anything, because little in this feature set carries strong signal for this target.

Where it's wrong

The worst prediction errors cluster at 1–2 impressions, where gsc_avg_position is an extremely noisy statistic — a single unusually-ranked query can swing the average sharply, and same-day behavioral features carry no information about that. Mean absolute error by impression bucket: 14.6 (0–10 impressions) vs. ~9.1–9.7 for every higher-volume bucket.

Limitations & Honest Framing

  • Unbalanced panel: only 36.7% of March rows have GSC data available, and unavailability is not random — it skews toward clients whose GSC history starts later in the panel. Findings describe only the covered slice.
  • Undefined-target exclusion: dropping zero-impression rows removed 42% of otherwise-available rows, skewing the modeled population toward content that already had some visibility.
  • Observational, not causal: the CTR-vs-position relationship is a validated association, not evidence that changing rank causes more clicks for any specific page.
  • Model result does not generalize: the negative R² is specific to this feature set, this window, and this lane; it is not a claim that no signal exists anywhere in FlyRank's broader data, only that these 5 same-day behavioral features do not carry it.

All claims in this paper use directional, decision-support language deliberately — observed, measured, directional — never causal or predictive certainty.

Ranked Recommendations

Built from the validated baseline rule, not the unvalidated model. 6,036 unique content items were flagged VISIBLE_BUT_POOR_RANK in the March 2026 slice.

  1. Prioritize items flagged across most or all of the month, not single-day spikes. Why: items flagged 25–31 days out of 31 reflect a stable, persistent pattern; items flagged only 1–2 days are more likely noise. Weight days_flagged alongside score, not score alone.
  2. Treat the queue as a shortlist for human review, not an automated action list. Why: the rule reflects observed volume × position gap only — it says nothing about content quality, technical SEO, or backlinks, none of which are in this dataset.
  3. Do not deploy the regression model in its current form. Why: it did not beat a naive baseline under honest validation. Shipping it would create false confidence, not real prioritization value.
  4. Re-verify the CTR-vs-position signal quarterly before continuing to rely on this rule. Why: the rule's entire justification rests on that one validated relationship holding over time; if it stops holding, the rule should pause.
  5. Never use this queue to justify budget, headcount, or contract decisions without a human strategist's sign-off. Why: association, not causation — a page being flagged does not guarantee a fix will work.
